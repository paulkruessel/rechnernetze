Datenstruktur (Liste) Nickname, IP Adresse, UDP Port
Register Vorgang:
Client -> Server mit Nachrichtenformat:
NICKNAME(16 byte)IP(4 byte)UDP(2byte)
Server schreibt client in Liste
Server -> Client
Liste als bytes

Logoff Vorgang

Update Vorgang Dazu
Server -> alle Clients
Neuer Client drin
Clients akutalisieren ihre eigene Liste

Update Vorgang Entfernenen
Server -> alle Clients
entfernter Client drin
Clients akutalisieren ihre eigene Liste

Broadcast Vorgang:
Client -> Server
Nachricht kommt vom Server in bytes an
Server schickt nachricht an alle verbundenen clients


Connect Vorgang:
Client A möchte sich mit Client B verbinden:
Client A --UDP--> Client B mit Nachricht
IP-Adresse(A)TCP-Port(A)
Client B antwortet per UDP mit ACK
Client B --TCP--> Client A sock.connect()

Message Vorgang:
Client A schickt per etablierter TCP Verbindung Client B eine Nachricht in bytes

Nachrichtenformat:
JSON-Länge(4bytes);JSON Binary

struct user:
{
    "nick": string,
    "ip_addr": string,
    "udp_port": string
}

struct message:
{
    "type": string,
    "user": user,
    "userlist":user[]
    "msg": string
}

Message Register Request
{
    "type":"REGISTER",
    "nick":"NICKNAME",
    "udp":12345
}
Beschreibung: Ein Client meldet sich beim Server an und uebergibt Nickname und eigenen UDP-Port.
Richtung: client->server

Message Register Response
{
    "type":"REGISTER_OK"
}
Beschreibung: Der Server bestaetigt eine erfolgreiche Registrierung.
Richtung: server->client

Message Register Fail
{
    "type":"REGISTER_FAIL"
}
Beschreibung: Der Server lehnt eine Registrierung ab, wenn REGISTER ungueltig, unvollstaendig oder mit leeren Feldern ist.
Richtung: server->client

Message Message Fail
{
    "type":"MESSAGE_FAIL"
}
Beschreibung: Der Server lehnt eine ungueltige, unvollstaendige oder nicht erlaubte Nicht-REGISTER-Nachricht ab.
Richtung: server->client

Message User List Full
{
    "type":"USER_LIST"
    "userlist":user[]
}
Beschreibung: Vollstaendige Liste aller aktuell registrierten Nutzer.
Richtung: server->client

Message New User
{
    "type":"USER_JOINED",
    "user":user
}
Beschreibung: Delta-Update, dass ein neuer Nutzer beigetreten ist.
Richtung: server->client

Message User Disconnect
{
    "type":"USER_LEFT",
    "user":user
}
Beschreibung: Delta-Update, dass ein Nutzer den Chat verlassen hat.
Richtung: server->client

Message Client to Client
{
    "type":"MESSAGE",
    "user":user,
    "msg": string
}
Beschreibung: Direkte Chat-Nachricht zwischen zwei Peers ueber eine bestehende Peer-Verbindung.
Richtung: client->client

Message Client to Client Fail
{
    "type":"MESSAGE_FAIL"
}
Beschreibung: Ein Peer meldet, dass eine direkte Client-Nachricht ungueltig, unvollstaendig oder nicht verarbeitbar war.
Richtung: client->client

Message Peer Invite
{
    "type":"PEER_INVITE",
    "user": user,
    "tcp_ip": string,
    "tcp_port": int
}
Beschreibung: UDP-Anstoss zum Aufbau einer direkten Peer-Verbindung; enthaelt die TCP-Zieldaten des Initiators.
Richtung: client->client

Message Peer Invite Ack
{
    "type":"PEER_INVITE_ACK",
    "user": user
}
Beschreibung: UDP-Bestaetigung, dass der Peer die Einladung erhalten hat und die direkte Verbindung aufbauen wird.
Richtung: client->client

Message Peer Disconnect
{
    "type":"DISCONNECT"
}
Beschreibung: Optionales TCP-Signal zum sauberen Beenden einer direkten Peer-Verbindung.
Richtung: client->client

Broadcast Server to Client
{
    "type":"BROADCAST",
    "broadcasting_user":user
    "msg": string
}
Beschreibung: Vom Server an alle registrierten Clients weitergeleitete Broadcast-Nachricht.
Richtung: client->server (eingehend), server->client (weitergeleitet)
